# NSH 0.7.0 upgrade

Locator: `odd/tasks/nsh-0-7-0.md` · Engram mirror: `odd/nsh-0-7-0/tasks` (project `exact_mobile`, where the NSH notes live)

## Objective

Move the app from NSH 0.6.1 to 0.7.0 (released 2026-11-25) and keep every feature working.

## Why

0.7.0 ships the fix for [longbridge/nsh#2448](https://github.com/longbridge/nsh/issues/2448) (PR #2803), so the
`import "websocket";` workaround in `feed.ts` can go. It also has an iOS fix for a bottom sheet whose input focuses as
it opens (PR #2781), which may be the blank New Task sheet found on 0.6.0 and 0.6.1.

## Scope and constraints

- Branch `chore/nsh-0.7.0` from `main` (ae0665c).
- CLI and runtimes via `nsh update`; crate `nsh-core` to 0.7.0; `NSH_TAG` to v0.7.0; `make embed-libs`.
- Remove the `websocket` side-effect import from `feed.ts`.
- `native/` host code does not change (only the ignored `native/libs` is refreshed).
- TDD: strict (project setting). Runner: `make check`, `make test`. The packaging feature choice happens only in
  `nsh package`, which the headless tests do not run, so T2 is checked on device, not with a new test.
- Delivery: `ask-on-risk`; forecast well under 400 changed lines; no push.

## Breaking changes checked against the app

- Pointer presses on iOS and macOS no longer move keyboard focus (#2783). The New Task title uses `autoFocus`.
- Android `ContextMenu` with `items` shows the system popup menu (#2549). `pages/Tasks.tsx` uses `trigger` with
  `MenuItem` children.
- Rust struct literals that need `..Default::default()`: none of the named structs are used in `rust/src`.
- Speech, desktop windows, Clipboard, Notifications and the updater are not used.

## Findings

- Android, New Task sheet opened with the keyboard: on 0.7.0 the sheet stays low and the keyboard covers the form
  (only the header and the title's top edge show; reproduced twice). On 0.6.1 the same sheet went too high, with the
  header and title off the top of the screen. It was broken before and is still broken, in the other direction.
- iOS Settings avatar looked like a 51 x 64 pt capsule. Not a bug: the avatar's layout box is 64 x 64 pt (the name
  starts at x 112 pt), and the stored photo (256 x 256 JPEG, from the simulator's test photo IMG_0007, 1000 x 1000) is
  a 4:5 portrait padded with white bars, which blend into the white card. The visible part is 80% of the width
  (51 of 64 pt). No change.
- iOS: a tap outside the open date calendar also closed the New Task sheet. Not compared with 0.6.1.
- Testing incident: a menu that stayed open turned a later tap into Delete and removed the task "Zcccx" on the
  simulator. It was restored byte for byte from the SQLite file (id 4, category 2, 2026-11-18 09:30, not done) and
  the app shows it again. A checkbox toggled by a stray tap was set back too.
